OpenOneRec 架构 × 生成式推理负载 深度解析

生成式推荐把「检索」变成「自回归生成候选 itemic token」。这意味着推理不再是向量内积，而是 prefill + decode 的编解码负载、KV cache 显存、以及「思维 CoT + 束搜索」叠加的算力放大。 前半部分拆解端到端架构流水线（Item as Tokens → 两阶段预训练 → SFT / On-Policy 蒸馏 → Rec-RL → 评测），后半部分基于 verl_rl/recipe/onerec/ 与 benchmarks/ 的真实参数，量化每条请求的负载构成，并给出优化方向。并基于 Ascend 910B（400 TFLOPS BF16 · 1.6 TB/s · 64 GB）给出吞吐/时延预算、显存预算与负载谱。

02

数据管道 & Itemic 词表（Item as Tokens）

核心思想：把「物品」当成一种独立模态，压缩成 3 个层级码，用与文本统一的 token 空间表达——这是整条流水线的地基。

03

预训练 · 两阶段 + 缩放律

先「词-文本对齐」再「全参数共预训练」；推荐语料与通用语料混合以抵抗灾难性遗忘，并遵循可预测的缩放律。

04

后训练 · SFT → On-Policy 蒸馏 → Rec-RL

三步走：SFT 恢复指令遵循 → On-Policy 蒸馏恢复通用推理 → GRPO 强化学习直接优化推荐命中。抽象参数（arc 参数化）也在 RL 阶段统一实现。

05

评测 · RecIF-Bench 能力金字塔 & 迁移

RecIF-Bench 用「4 层能力金字塔 × 8 任务 × 3 域」系统评估指令遵循与推荐能力的协同；用 Amazon 10 数据集验证跨域迁移。

06

模型家族 & 关键设计点

基于 Qwen3 骨干、结构严格不变，只扩展词表；Standard 与 Pro 的区别仅在预训练语料规模。

07

推理部署架构 · 训练(Rollout) vs 评测/在线

OpenOneRec 的推理负载跑在两套由 Ray 编排、vLLM 承载的拓扑里：RL 训练期用「单控制器 + colocated Actor/Rollout/Ref Worker + FSDP2 分片 + 内嵌 vLLM rollout（TP=1）」； 评测/在线期用「RayVllmGenerator + 数据并行多 vLLM Worker（TP 同节点分组）」。

08

一条推理请求的负载全景

一条推荐请求从「用户历史 → itemic 上下文」到「命中 K 个候选」的完整负载链：数值越小 = 负载越轻。深色节点可点击查看源码依据。

💡 核心矛盾：decode 访存密集 × beam/128 候选放大 × 10K 长 prompt KV，三者叠加是生成式推荐负载的关键特征。

10

两阶段生成 & 束搜索 · 负载放大链路

训练(Rollout)与评测(Generator)共用同一两阶段范式：先采样思维 CoT，再把 CoT 拼回 prompt 做束搜索。每一步都会重复 prefill。

③ 模型与注意力

KV cacheKey-Value 缓存注意力历史缓存；8B/bf16/GQA-8 ≈ 144 KB/token，S=10K 时 1.51 GB/序列
prefill预填充一次性并行前向吃下整个 prompt，生成 KV cache；算力界（compute-bound）
decode解码逐 token 自回归生成；访存界（memory-bound，每步读全量权重）
bf16 / fp816 / 8 位浮点权重与 KV 的数值格式；fp8 KV 可再省一半显存

④ 推荐范式与生成
itemic token物品词元物品经 RQ-Kmeans 量化出的三层码（s_a/s_b/s_c），推荐输出固定 3 个 token
SIDSemantic ID（语义 ID）模型生成的 itemic 三元组序列，如 <|sid_begin|><s_a><s_b><s_c>
PIDPhoto/Item ID物品真实 ID；评测时把 SID 映射回 PID 算召回
RQ-KmeansResidual K-Means残差 K 均值量化：逐层对残差聚类，训练 3×8192 码本
beam search束搜索每步保留 B 条最优序列；beam=32 时 decode 算力 ×32（prefix cache 下显存不放大）
CoTChain-of-Thought（思维链）先生成推理再给答案；enable_thinking=True 时推荐任务才有 CoT 与二次 prefill
enable_thinking思维开关线上推荐默认 False → 单阶段「恒前缀 + beam search」，无 CoT
<|sid_begin|>SID 起始符恒前缀：拼在 prompt 后强制模型进入「生成 SID」状态
⑤ 系统优化
prefix cache前缀缓存（Radix/PagedAttention）复用相同前缀的 KV：同一 prompt 的 32 条 beam 共享前缀，decode 不重算

activation offload激活卸载训练期把激活换出到主存；RL rollout 显存腾挪手段
