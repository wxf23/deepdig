1. 引言

随着大语言模型(LLM)、多模态模型等AI应用的快速发展，AI处理器需要同时支撑大规模分布式训练和低延迟高吞吐推理，对算力密度、内存容量、互连带宽以及编程灵活性提出了更高要求。华为在第一代达芬奇(Da Vinci)架构（Ascend 910）成功的基础上，推出了第二代达芬奇架构，其核心产品即为Ascend 910B。

Ascend 910B针对Transformer类大模型的计算特征进行了深度优化：将Cube矩阵核与Vector向量核从同核耦合改为异构分离部署，按1:2灵活配比以更好匹配大模型中矩阵运算与逐元素运算的算力比例；升级为HBM2e高带宽内存，显著提升内存容量和带宽；新增FixPipe硬化加速通路、核间同步机制、跨卡HCCS缓存一致性互连等关键特性，在BF16/FP16精度下实现了算力翻倍级提升，成为支撑千亿、万亿参数大模型训练与推理的主力算力平台。

本白皮书系统介绍Ascend 910B NPU的硬件架构，重点阐述第二代达芬奇架构中Cube/Vector核分离设计的微架构创新、配套多级存储系统、核间同步机制、互连拓扑以及CANN软件栈，并通过原生SVG矢量图直观呈现各层级架构细节。

2. 芯片架构概述

Ascend 910B是一款基于第二代达芬奇(Da Vinci)架构的高性能AI处理器，采用先进工艺制造。相比第一代Ascend 910，其最核心的架构变革是Cube Core(AIC)与Vector Core(AIV)分离部署：矩阵计算单元和向量计算单元从共享同一Scalar调度器的同核设计，演进为各自拥有独立Scalar调度器的异构核，按1:N（典型1:2）比例灵活组合。这种分离式架构让矩阵计算和向量计算能够完全异步独立执行，消除了不同计算类型间的资源争抢，显著提升算子融合效率和硬件利用率。

Ascend 910B的核心设计改进包括：

  • 异构核分离：Cube Core与Vector Core独立部署，各自配属独立Scalar单元和指令流，支持完全异步并行；
  • 灵活配比：1个Cube Core搭配2个Vector Core，精准匹配大模型中GEMM与Attention/Softmax等操作的算力比例；
  • BF16原生支持：原生支持BF16数据格式，更好适配大模型训练的数值精度需求；
  • FixPipe硬化加速：在数据通路上硬化实现量化/反量化、激活函数、数据格式转换等操作，实现"随路计算"零开销；
  • 核间同步原语：硬件支持CrossCoreSetFlag/WaitFlag，实现AIC与AIV间、同类核间的高效同步；
  • HCCS缓存一致性互连：华为自研缓存一致性总线，支持跨卡直接内存访问，构建大规模分布式训练集群；
  • 大容量L2 Cache：增大片上共享缓存容量，提升大模型权重和KV Cache的片上复用率。

3. 第二代Da Vinci AI Core微架构

第二代达芬奇架构对AI Core进行了解耦重构。一个逻辑上的"AI Core"不再是单一计算核，而是由1个Cube Core (AIC) + 2个Vector Core (AIV)组成的异构计算组合。三个核各自拥有独立的Scalar控制单元、独立指令流、独立本地存储，通过片上网络和核间同步机制协同工作。

图3-1：第二代Da Vinci架构AI Core组合示意图（1 AIC + 2 AIV 分离部署）

3.1 Cube核(AIC)与Vector核(AIV)分离部署

分离架构是第二代达芬奇相对于第一代的核心架构变革，其设计动机和优势在于：

第一代（同核耦合模式·910）

  • Cube和Vector共享1个Scalar调度器
  • 同一AI Core内Cube/Vector/DMA指令串行发射到不同队列
  • Cube与Vector算力绑定，比例固定为硬件设计值
  • 适用于矩阵运算与向量运算比例相对固定的CNN类模型

第二代（分离模式·910B）新架构

  • AIC(Cube)和AIV(Vector)各自拥有独立Scalar单元
  • 三核可同时运行完全独立的指令流，真正异步并行
  • 配比灵活（典型1:2），更匹配LLM中Attention/Softmax等Vector密集型操作
  • 算子可按类型独立调度：Cube算子只占AIC，Vector算子占AIV
  • 融合算子可同时启动AIC+AIV，通过CrossCore同步协同

在Kernel类型上，Ascend C支持三种启动类型：

  • __cube__：仅在AIC（Cube核）上执行，用于纯矩阵算子；
  • __vector__：仅在AIV（Vector核）上执行，用于纯向量算子；
  • __mix__(1, 2)：同时在1个AIC+2个AIV上执行，用于Cube-Vector融合算子（如FlashAttention）。

3.2 Cube Core矩阵计算单元

AIC(Cube Core)专职负责矩阵乘法(GEMM)和卷积运算。其核心计算阵列仍是高性能的16×16×16三维MAC阵列，每周期可完成16×16与16×16矩阵相乘即4096次FP16乘加运算。第二代架构中Cube单元新增了对BF16的原生支持，并优化了L0C容量和数据通路以支持更大规模矩阵分块。

图3-2：AIC(Cube Core)内部数据通路

Cube单元支持的精度格式包括：FP32、TF32、FP16、BF16、INT8等。矩阵操作数使用专门设计的分形(Fractal)存储格式——左矩阵FRACTAL_ZZ、右矩阵FRACTAL_ZN、结果FRACTAL_NZ，针对16×16基本块的连续存储设计，最大化片上数据复用率，减少DRAM访问次数。

3.3 Vector Core向量计算单元

AIV(Vector Core)专职负责向量类计算，每个AIV拥有独立的Scalar控制单元和独立的Unified Buffer，可独立调度和执行。Vector Core采用SIMD架构，主要承担神经网络中的逐元素运算、激活函数、归一化、Softmax、Reduce、数据类型转换等操作。

图3-3：AIV(Vector Core)内部结构

AIV的Unified Buffer容量为512KB，是Vector计算的核心数据暂存区。Vector ALU支持丰富的数据类型：FP32、FP16、BF16、INT32、INT16、INT8等，并内置了Exp/Log/Sqrt等超越函数的硬件加速单元，无需软件近似即可快速完成这些常见运算。

3.4 Scalar标量控制单元

在分离架构下，每个AIC和每个AIV都拥有独立的Scalar单元。Scalar单元是每个核的控制核心，其职责包括：

  • 独立取指译码：每个核从自己的ICache（32KB）中取出指令，译码后发射到本核的各执行单元；
  • 标量运算：执行地址计算、循环计数、条件判断等标量操作（DCache 32KB缓存标量数据）；
  • 指令发射：将Cube/Vector/MTE指令发射到对应指令队列，不同核的指令流完全独立；
  • 同步管理：执行SetFlag/WaitFlag完成核内流水同步，执行CrossCoreSetFlag/WaitFlag完成核间同步。

由于Scalar单元计算能力相对有限，性能优化的重要原则是：尽量减少核内分支判断和复杂标量计算，将Tiling（数据切分参数）计算放在Host侧CPU或AI CPU上完成后通过TilingData结构体传入Kernel。

3.5 存储层次结构

Ascend 910B继承并优化了达芬奇架构的多级片上存储层次。与第一代不同的是，由于AIC与AIV分离，Cube侧的L0/L1与Vector侧的UB分别隶属于不同的物理核，AIC与AIV之间的数据交换需要通过Global Memory(GM)或专门通路完成。

典型数据流：

  • 纯Vector计算：GM → UB → Vector ALU → UB → GM
  • 纯Cube计算：GM → L1 → L0A/L0B → Cube → L0C → FixPipe → GM/L1
  • Cube-Vector融合（如FlashAttention）：GM→L1→L0A/L0B→Cube→L0C→FixPipe→GM→(CrossCore同步)→UB→Vector→GM

3.6 FixPipe硬化加速通路第二代增强

FixPipe是位于AIC内L0C之后的硬化加速通路，它将神经网络中常见的后处理操作直接实现在数据搬运通路上，实现"计算-搬运-后处理"三位一体的随路执行，无需占用Cube或Vector的额外算力和指令周期，显著提升算子性能。

FixPipe支持的硬化操作包括：

  • 量化/反量化：S32→FP16/BF16/INT8/INT4、FP32→FP16/BF16/INT8/INT4等多种精度转换；
  • 激活函数：ReLU、PReLU、LeakyReLU等常见激活函数随路计算；
  • 数据格式转换：Channel Merge/Channel Split分形尺寸变换，支持S8/U8下16×16→16×32、S4/U4下16×16→16×64、FP32下16×16→16×8等通道合并/分裂；支持NZ→ND数据格式转换。

4. 芯片整体架构

Ascend 910B采用SoC架构，在单芯片上集成了多个AI Core组合（AIC+AIV）、AI CPU集群、大容量L2 Cache、HBM2e内存控制器、STARS硬件任务调度器、SDMA系统DMA引擎、PCIe Gen4/5主机接口以及HCCS芯片间互连接口。

图4-1：Ascend 910B芯片整体架构框图

注：图中核数配置为典型示例（20 AIC+40 AIV），实际产品不同SKU可能有不同核数配置。

4.1 AI计算集群

Ascend 910B芯片内集成了多组AI Core组合（典型配置为20组左右，即20个Cube Core + 40个Vector Core），这些Core分布在多个Cluster中，通过NoC片上网络互连，共享大容量L2 Cache。

在Kernel启动时，开发者可根据算子类型选择启动核数：

  • 纯Cube算子（如GEMM）：numBlocks设为AIC数量；
  • 纯Vector算子（如Element-wise Add、Softmax）：numBlocks设为AIV数量；
  • Cube-Vector融合算子（如FlashAttention）：numBlocks设为AI Core组合数，硬件会同时调度AIC和对应的AIV协同执行。

4.2 AI CPU子系统

芯片集成了多个自研ARM架构CPU核心（组成多个Cluster），每个AI CPU核心支持物理双线程。AI CPU的主要作用：

  • 执行Device侧操作系统（类似NPU上的"小操作系统"），负责运行时管理、资源调度；
  • 执行逻辑复杂、不适合在AI Core上运行的CPU类算子；
  • 支持Tiling下沉，即把原本在Host侧的切分逻辑计算放到Device侧执行，减少Host-Device交互开销。

AI CPU拥有独立的L1/L2/L3 Cache层次，并通过硬件支持的全局缓存一致性机制与AI Core子系统交换数据。

4.3 内存子系统

Ascend 910B升级为HBM2e高带宽内存，典型配置64GB容量，提供约2TB/s的峰值带宽，相比第一代910的32GB/1.2TB/s实现了容量和带宽的翻倍，能够支撑更大参数量模型的训练以及更长上下文的KV Cache存储需求。

在HBM和AI计算单元之间，芯片配置了更大容量的L2 Cache（8~16MB级别），并提供了精细化的Cache管理能力：

  • Cache Hint策略：程序员可通过软件接口提示硬件某块数据是否应分配进L2 Cache（non-allocate策略），避免一次性数据污染Cache；
  • Sector Cache：支持128B Sector粒度的Cache管理，提高小数据访问效率；
  • CMO(Cache Maintenance Operation)：支持SDMA对L2 Cache的预取(Prefetch)、回写(Writeback)、无效化(Invalid)、冲刷(Flush)等管理操作。

4.4 STARS任务调度器升级

Ascend 910B搭载STARS硬件任务调度器，作为全芯片任务和资源调度的核心：

  • 支持Host侧下沉大量任务流到Device侧，由STARS硬件自动完成任务预取、依赖调度、结果上报，将端到端调度开销降低至ns级；
  • 使用专用HSCB(High Speed Control Bus)高速控制总线与AI Core交互，避免与数据通路NoC竞争；
  • 支持将AIC/AIV/SDMA等资源切分成最多16个资源池，支持虚拟机级别的算力隔离；
  • 支持最多8个Group分组调度，按Die/Cluster分组调度可更好利用L2 Cache局部性；
  • 集成实时Profiling能力，可记录Task执行时间轨迹、计算开销、带宽、功耗等数据。

4.5 片上互连与IO

Ascend 910B提供了完善的互连体系，支撑单机多卡和大规模集群扩展：

  • PCIe 接口：支持PCIe Gen4 x16（部分版本支持Gen5），双向带宽~32GB/s以上，用于与Host CPU通信；支持RC/EP双模，兼容多种服务器拓扑；
  • HCCS互连：华为自研缓存一致性互连总线(Huawei Cache Coherent Switch)，支持多颗Ascend 910B芯片直接高速互连，实现缓存一致的跨卡内存访问，无需Host中转，是构建8卡/16卡等多卡训练服务器节点的关键；DataCopy类API可直接通过HCCS物理链路进行跨卡数据搬运；
  • NoC片上网络：全芯片统一地址空间，连接所有计算、存储、IO模块，提供高带宽低延迟的片上通信。

5. 计算数据流、核间同步与流水线

第二代分离架构引入了新的核间同步需求：AIC与AIV是独立核，在融合算子中需要协同工作。硬件提供了CrossCoreSetFlag/CrossCoreWaitFlag原语实现高效核间同步。

核间同步机制

CrossCore同步基于硬件计数器实现：CrossCoreSetFlag对指定flagId的计数器+1，CrossCoreWaitFlag在计数器为0时阻塞等待，计数器大于0时计数器-1并继续执行。支持三种同步模式：

  • 模式0（同类核全局同步）：所有AIC核之间的同步，或所有AIV核之间的同步，实现全局栅栏；
  • 模式1（AIV间同步）：同一AI Core组合内两个AIV核之间的同步；
  • 模式2（AIC-AIV同步，1:N）：AIC执行SetFlag后对应的所有AIV才能继续；所有AIV都执行SetFlag后AIC才能继续。这是融合算子最常用的模式。
图5-1：融合算子中AIC-AIV协同工作流程（模式2同步）

核内三级流水线

在单个AIC或AIV核内部，仍然采用CopyIn→Compute→CopyOut三级流水并行，并通过DoubleBuffer机制实现搬运与计算的重叠。由于第二代架构下各核拥有独立指令流，Cube计算、Vector计算、数据搬运三者可以实现真正的跨核并行——AIC在做矩阵计算的同时，AIV可能在做前一块数据的向量后处理，DMA引擎在搬运下一块数据，三者完全重叠，达到极致的硬件利用率。

6. CANN软件栈与AscendC编程

Ascend 910B由配套的CANN异构计算架构提供完整软件支持。CANN向上兼容PyTorch、TensorFlow、MindSpore、ONNX Runtime等主流AI框架，向下充分释放第二代Da Vinci分离架构的硬件算力。

图6-1：支持Ascend 910B的CANN软件栈层次

Ascend 910B的软件栈有几个针对分离架构优化的关键点：

  • AscendC核类型区分：使用__cube__/__vector__/__mix__(1,2)函数类型限定符明确指定Kernel运行在哪类核上，__mix__(1,2)表示同时启动1个AIC和2个AIV组成融合执行；
  • 核间同步API：提供CrossCoreSetFlag/CrossCoreWaitFlagAPI供融合算子实现AIC与AIV间的同步；
  • HCCL集合通信深度优化：针对HCCS互连和大规模集群拓扑优化AllReduce等集合通信原语，支持计算与通信重叠，是大模型分布式训练性能的关键；
  • SuperKernel融合技术：将多个子Kernel二进制融合为一个超级Kernel在Device侧连续执行，减少任务调度开销，特别适合大模型中大量小算子的连续执行场景；
  • Tiling策略支持：支持Host侧Tiling和Tiling下沉到AI CPU两种模式，Tiling参数通过TilingData结构体传入Kernel，实现数据最优切分。

8. 总结

Ascend 910B作为华为第二代达芬奇架构的主力产品，其核心创新在于Cube/Vector异构核分离架构。通过将矩阵计算单元和向量计算单元解耦为独立的AIC和AIV核并按1:2比例组合，它精准匹配了Transformer大模型时代GEMM矩阵运算与Attention/Softmax等向量运算的算力配比需求；配合独立指令流、硬件核间同步、FixPipe硬化加速、HBM2e大容量高带宽内存、HCCS缓存一致性互连以及CANN软件栈的深度优化，Ascend 910B在大模型训练和推理场景中实现了性能、可编程性和扩展性的全面提升。

第二代达芬奇架构的关键设计要点包括：

  • 异构解耦：AIC与AIV独立部署、独立调度、独立执行，消除了同核架构下不同计算类型的资源争抢；
  • 灵活配比：1:2的Cube:Vector核比例针对LLM workload特征优化，向量算力翻倍提升；
  • 硬化加速：FixPipe通路将常见后处理操作下沉到数据搬运通路，实现零开销随路计算；
  • 高效同步：硬件级CrossCore原语为融合算子提供低延迟核间同步能力，支撑Cube-Vector深度流水并行；
  • 显存升级：HBM2e将显存容量和带宽均提升约一倍，缓解大模型内存墙问题，支撑更长上下文和更大Batch；
  • 集群扩展：HCCS缓存一致性互连为多卡分布式训练提供高带宽低延迟的芯片间通信基础；
  • 软硬协同：CANN软件栈从算子编程模型到编译器到通信库针对分离架构深度适配，充分释放硬件性能。

Ascend 910B是华为昇腾算力平台支撑大模型产业落地的主力产品，其架构设计思想——异构解耦、领域专用硬件加速、软硬件协同、缓存一致性大规模扩展——为后续Ascend 910C/950等新一代产品的持续演进奠定了坚实基础。
