1SHMEM 是什么：一句话与一张对比

在进入架构细节之前，先建立准确的"心智模型"。

💡
一句话定义：SHMEM 是面向昇腾 NPU 的对称内存（Symmetric Memory）通信库——每个参与方（PE）持有一块布局完全相同的内存堆，任何一方可以在自己的算子（AICore kernel）里直接读写别人的那块内存，不需要对方参与。这种"大家共享一片分布式内存"的编程模型称为 PGAS（Partitioned Global Address Space，分区全局地址空间）。
🌰
类比：把 8 个 NPU 想象成 8 栋格局完全相同的公寓楼（每层户型一模一样）。你想去 3 号楼拿东西，不需要 3 号楼的人帮你搬（点对点消息），也不需要广播给所有楼（集合通信）——你只要说"3 号楼 · 和我家相同位置的那间房"，快递通道就能直达。SHMEM 的 aclshmem_ptr(ptr, pe) 干的就是这个"地址翻译"。

1.1 与 MPI 消息模型的本质区别

MPI（消息传递）SHMEM（对称内存 / PGAS）
通信发起双方都要调用（send 必须配 recv）单边：只有发起方调用 put/get，对端无感知
地址知识不需要知道对方缓冲区地址必须知道对端对称地址（由对称堆保证可换算）
同步负担由消息语义天然携带需要显式 signal / fence / quiet / barrier
通信-计算关系多为"先通信后计算"两段式通算融合：通信指令内联在算子 kernel 里，与计算流水重叠
典型开销走框架栈（HCCL 等），批量引擎直驱（WQE/SQE/UB 流水），微秒级小消息也可用

注意：SHMEM 不是"取代 MPI/HCCL"，而是提供更贴近硬件、更细粒度的单边通信原语，常用于 MoE dispatch/combine、KV shuffle、AllReduce 融合算子等场景（见 examples 目录）。

1.2 双侧接口体系与"高阶 / 低阶"

SHMEM 的 API 分为 Host 侧（CPU 进程调用：初始化、堆管理、Team、下发 kernel）与 Device 侧（AICore 算子内联调用：RMA、AMO、同步）。Device 侧再分两层：

层级位置特点代表接口
高阶接口gm2gm/ · host/data_plane/屏蔽引擎细节，自动管理 buffer 与同步；默认 buffer 不支持并发aclshmem_put/get、aclshmem_amo_*、aclshmemx_signal_op
低阶接口engine/ 目录直接暴露引擎语义（WQE/SQE/sync_id），调用方自管 buffer 与同步，支持并发aclshmemx_roce_*、aclshmemx_udma_*、aclshmemx_sdma_*、aclshmemx_mte_*

高阶接口使用前需先 aclshmemx_set_mte_config / set_rdma_config / set_sdma_config / set_udma_config 预配置一块 UB scratch 与 sync_id（第 6 章展开）。

1.3 一个最小可运行的例子（UID 模式）

examples/init（节选 · UID 模式启动）
// rank 0 生成 UniqueID，由应用层广播给所有 rank（库不负责广播）
aclshmemx_uniqueid_t uid = ACLSHMEM_UNIQUEID_INITIALIZER;
if (my_pe == 0) aclshmemx_get_uniqueid(&uid);
broadcast(&uid);                          // 例如用 MPI_Bcast / 文件 / 手动分发

aclshmemx_init_attr_t attr = {};
aclshmemx_set_attr_uniqueid_args(my_pe, n_pes, local_mem_size, &uid, &attr);
aclshmemx_init_attr(ACLSHMEMX_INIT_WITH_UNIQUEID, &attr);  // 所有 PE 对称调用！

// —— 此时对称堆就绪，各 rank 同序同大小 malloc，偏移自动一致 ——
aclshmem_putmem(dst, src, n_bytes, dst_pe);
aclshmem_finalize();
⚠️
三条铁律（源码文档反复强调）：① init/finalize 必须每个 PE 都调用；② 除 my_pe 外 init 参数需一致；③ 各 rank 的 aclshmem_malloc/free 必须同序同大小——否则对称偏移错位，RMA 会读写到错误地址（第 3、5 章展开原理）。

2总体分层架构：三层两侧

整个系统可以切成三条横带：Host 控制面（慢路径，建好就走开）、Device 数据面（快路径，算子内联）、硬件层（真正搬数据的引擎与总线）。

🖼️ 图 2-1 · SHMEM 全景分层架构（hover 每个框可看说明；箭头 = 调用/数据流向）
图例：蓝箭头 = 控制流（Host→Device 任务下发）；彩色箭头 = 数据流（引擎→硬件通路）。控制面只在 init/建链阶段活跃；运行期数据完全走 Device 侧引擎直驱。

2.1 三层各自的职责边界

层解决什么问题关键机制性能特征
Host 控制面谁在哪儿（PE 发现）、内存怎么对齐、队列/权限怎么建Bootstrap（TCP KV / MPI）· MR 注册 · QP/队列创建 · state 镜像下发毫秒级，只在启动/建堆/分配时介入
Device 数据面算子内怎么高效搬数、怎么同步内联 C++（ACLSHMEM_DEVICE）· 地址换算 · 引擎直驱 · 同步原语微秒级，与计算重叠
硬件层真正把字节从 A 搬到 BMTE 流水 · SDMA 队列 · RoCE WQE/doorbell/CQ · UB EID/token由引擎微架构决定（第 6 章逐个拆）
🔑
理解架构的钥匙——"两个分离"：
① 控制面/数据面分离：CPU 只做一次性的建链与元数据交换，之后通信不再经过 Host（对比：传统方案每次通信都要 H2D→CPU→D2H 往返）。
② 高阶/低阶接口分离：易用性与极致性能兼得——高阶自动管理资源，低阶把 WQE/SQE 直接交给你，支持多核并发（每个核自己的 QP/sync_id）。
🔬 深入：Device 侧代码如何"长"在用户算子里？

所有 Device 接口都带宏 ACLSHMEM_DEVICE = __attribute__((always_inline)) __aicore__ __inline__：它们不是运行时库调用，而是在编译期被内联进用户 kernel。因此：

  • 算子包含 shmem.h 后，put/get 会展开为对引擎的寄存器写与搬运指令，零函数调用开销；
  • Host 侧发起的接口（data_plane）本质是 aclshmemi_putmem<<<block, 0, stream>>>(...) —— 把同样的 device kernel 通过 ACL stream 下发；
  • device_state 通过固定虚拟地址读取（aclshmemi_get_extra_context_addr(0)，位于 0x1800_0000_0000 − 1G − 32M 附近的元数据区），算子里不需要任何指针参数就能拿到全局状态。

3对称内存模型：一切单边通信的地基

SHMEM 的全部魔法都建立在一个事实上：同一逻辑对象在所有 PE 的堆里位于相同偏移。本章讲清楚这块堆怎么布局、地址怎么换算。

🌰
类比：把每个 PE 的堆想成一栋户型图完全相同的公寓楼。"我家书房"这个说法在任何一栋楼里都指向同一个相对位置——所以"3 号楼的书房"不需要门牌号码簿，只需要 楼号(PE) + 户型内位置(偏移)。SHMEM 存的不是全局地址，而是"户型内偏移"，用到时现场换算。
🖼️ 图 3-1 · 对称内存模型与地址换算（GVA 地址空间 → 各 PE 对称堆 → 偏移同构）
对称堆在 GVM（20T–24T） 预留区中顺序排布：PE k 的窗口 = 基址 + k×ALIGN_UP(heap_size,1G)。注意 heap_size 各 PE 必须相同（不对称时退化处理，日志告警）。

为什么元数据放固定地址？因为 device 侧代码没有"全局变量传参"机制——kernel 里用 aclshmemi_get_state() 直接读固定 VA，即拿到 Host 写好的运行时状态（mype、各 PE heap_base、topo_list、引擎配置……）。

🔬 深入：为什么"同序同大小 malloc"能保证偏移一致？

SHMEM 的分配器是确定性 first-fit：从堆底开始，找第一个能放下的洞。只要所有 PE 执行完全相同的分配/释放序列，分配器内部状态机就完全同步，任何时刻同一"分配序号"对应的偏移在所有 PE 上相同。这正是 init 文档强调三条铁律的原因——一次不对称的 malloc 就会让两边的"户型图"从此错位。

配套机制：每次 aclshmem_malloc/free 返回前，都会在控制面做一次全体 barrier（Config Store 上的 GroupBarrier），确保所有 PE 都完成本轮分配再继续——防止快慢进程导致的分配序列分叉。

4控制面：Bootstrap 与 Config Store

运行数据面前，必须先回答三个问题：谁参与（PE 发现）、内存登记在哪（元数据交换）、大家进度对齐了吗（控制 barrier）。这些全部发生在 CPU 侧控制面。

🌰
类比：Config Store 就像工地项目部（PE 0 的总台登记簿）——各施工队（PE）先到总台报到（connect + 握手），之后所有"材料清单"（内存 slice 描述符）都抄送到登记簿上互相传阅（allgather），每完成一道工序都到总台打个卡（barrier）。而真正开工后的材料运输（数据面）走的是另一套系统，不经过项目部。

6数据面四大引擎：MTE · SDMA · RDMA · UDMA

这是全书硬件原理的核心。四个引擎对应四条不同的硬件通路，编程模型各不相同——但都被同一套对称地址换算喂进数据。

🌰
类比一张"物流网络"：
🚚 MTE = 你自己的手推车——最快，但要你亲自推（占 AICore），且每次推的量受手推车大小限制（UB staging）；
📋 SDMA = 后勤搬家公司——填一张工单（SQE）塞进它的排队窗口，公司自己搬，你去干别的；
✈️ RDMA/RoCE = 跨城货运航线——要报关（WQE + rkey）、走机场（网卡）、有回执（CQE），距离远但一次能运很多；
🏭 UDMA/UB = 新一代统一物流网（灵衢）——每个仓库有"码头号"（jetty）和"提货令牌"（token），全网统一编址（EID），还支持"到货自动发短信"（WRITE_WITH_NOTIFY）和"入仓自动合并"（WRITE_WITH_REDUCE）。

MTE：Memory Transfer Engine（AICore 旁路搬运引擎）

硬件本体：每个 AICore 旁挂的专用搬运算术单元，分两个流水级——MTE2：GM → UB MTE3：UB → GM。它不是独立设备，而是核内流水线的一部分，因此启动延迟最低；代价是要占用 AICore 的执行流（发搬运指令、等事件）。

跨卡能力：在 910 上，MTE 的 GM 访问可以经 HCCS 直达同机其他 NPU 的 GM（对端内存被映射进本地可寻址空间，load/store 语义）；A3 片内双 Die 之间走 SIO。所以"远端读"在本机范围内其实是一条普通访存路径。

auto remote_ptr = aclshmem_ptr(src, pe);              // ① 对称地址换算
uint64_t block_size = ub_size / sizeof(T) * sizeof(T); // ② 按 UB 容量分块
for (uint64_t i = 0; i < loop_times; i++) {
    aclshmemi_copy_gm2ub(buf, remote_ptr + i * repeat_elem, block_size);  // ③ 远端GM → UB
    AscendC::SetFlag<AscendC::HardEvent::MTE2_MTE3>(sync_id);              // ④ 通知 MTE3
    AscendC::WaitFlag<AscendC::HardEvent::MTE2_MTE3>(sync_id);            // ⑤ 等 UB 就绪
    aclshmemi_copy_ub2gm(dst + i * repeat_elem, buf, block_size);         // ⑥ UB → 本地GM
    if (i != loop_times - 1) { AscendC::SetFlag<AscendC::HardEvent::MTE3_MTE2>(sync_id); } // 尾块免等待
}
🔬 深入：为什么"尾块免等待"？AMO 的两条路线？
  • 尾块免等待：循环里每轮要先把 UB 归还给 MTE2 复用（SetFlag MTE3_MTE2）；但最后一块不再有下一轮搬运，这个 flag 留到 kernel 结束统一回收即可——省一次事件等待。
  • AMO 两条路线（__NPU_ARCH__==3510 即 950 区分）：950 直接 AscendC::AtomicAdd/Cas/Exch 硬件原子；910 先把 add 值写进 UB，SetAtomicAdd<T>() 设置 MTE 写命令的原子标志，再 copy_ub2gm——原子性由 MTE 写通路保证。
  • Host 内存：MTE 同样覆盖 D2H/H2D（本机）与 D2rH/rH2D（远端 Host，借助 Host 连接映射区 48T）。

SDMA：System DMA（STARS 引擎，队列化搬运）

硬件本体：独立于 AICore 的系统级 DMA 引擎（STARS），有自己的通道队列。AICore 只负责"填工单 + 按门铃"，搬运由引擎异步完成——AICore 被解放出来继续算。

平台：仅 __NPU_ARCH__==2201（910A3 档）。950 上由 UDMA 取代。

SDMA 的 quiet 是"本核队列"粒度：一次 quiet 即覆盖发给所有 SDMA 可达 PE 的请求（对比 RDMA/UDMA 需要按对端 quiet）。

  • 通道分配：init 时 SDMA transport manager 建好通道（AICPU/AIV 共享 sdma_workspace），通道信息（sq_base/深度/stream_id）写入 device 可见的元数据；算子里 aclshmemi_get_channel_info 直接取。

  • notify/wait：SDMA 提供配套同步原语——生产者发 notify_record（type=6 SQE），消费者 wait 该记录，实现"搬运完成通知"（examples/notifywait）。

RDMA / RoCE：跨节点远程直接内存访问

硬件本体：RoCE 网卡（本仓支持三种后端：IN_DIE 片内XSCALE（云脉）HNS 1825）。网卡绕过两端 CPU 直接读写对端注册内存（MR），跨机主力通路。

编程模型（verbs 风格）：每对 (pe, qp_idx) 一个 QP（Queue Pair）——发送队列 SQ + 完成队列 CQ。AICore 构造 WQE（工作队列元素）→ 写入 SQ → 敲 doorbell → 网卡取 WQE 执行 → 完成后写 CQE 到 CQ → 轮询 CQ 确认完成。内存需先注册成 MR 拿到 lkey/rkey（本地/远程访问键）。

🖼️ 图 6-3 · RDMA 数据面：WQE → SQ → doorbell → 网卡 → 对端 HBM，CQE 回执
典型时序：①UB 构造 WQE → ②MTE3 搬到 SQ → ③写 doorbell → ④网卡发包直写对端 → ⑤CQE 回执 → ⑥poll/quiet。注意 owner_bit 翻转（WQE 环所有权交接）与 signaled 位（要求生成 CQE）。
src/device/gm2gm/engine/rdma_backends/rdma_device_backend_in_die.hpp（节选）
uint64_t owner_bit = (cur_head >> 13) & 0x1;            // WQE 环每 8192 项翻转所有权
byte4  = opcode & 0x1F;                                // RDMA_WRITE=3 / RDMA_READ
byte4 |= ((~owner_bit) << 7) & (1 << 7);              // owner 位
byte4 |= 1 << 8;                                      // IBV_SEND_SIGNALED：完成时生成 CQE
*(u32*)(wqe + 20) = wr.rkey;                           // 对端远程键
*(u64*)(wqe + 24) = (u64)wr.remote_addr;               // 对端虚拟地址
// —— doorbell：DB_TAG=qp_num | DB_CMD=0 | DB_PI=head | DB_SL ——
doorbell_info |= sq_context->wqn;
doorbell_info |= ((u64)cur_head % 65536) << 32;
// 经 MTE3 把 doorbell 值从 UB 写入网卡寄存器地址（db_addr）
🔬 深入：三个后端的差异、原子操作与并发约束
  • 编译期多态：后端以模板参数 aclshmemi_rdma_backend_t B 静态分发（aclshmemi_roce_fill_wqe<B, OP> / ring_sq_doorbell<B>），零运行时开销；WQE/doorbell 位域由各后端特化实现。

UDMA：统一 DMA（UB 灵衢总线，950 代际）

硬件本体：950 的 UB（Unified Bus，灵衢）统一互联——华为新一代数据中心统一总线协议，统一 scale-up/scale-out，提供 UBMEM（内存语义）与 URMA（统一远程内存访问）能力。寻址不再用 IP/rkey，而用 EID（16 字节端点地址）+ jetty（码头） + token（令牌）。

7同步与内存保序：让"快"不变成"乱"

单边通信把同步责任交还给了程序员。SHMEM 提供三层原语：点对点 signal（等一个变量）、集合 barrier/sync（等一群 PE）、quiet/fence（等自己的写落地）。

7.1 点对点：signal_wait_until 自旋等待

生产者用 signal_set/add（或 put-with-signal）写对端 signal 变量；消费者用 wait_until / test 系列自旋轮询该变量，支持 eq/ne/gt/ge/lt/le 与 all/any/some（+vector）组合。

⚠️
cacheline 独占：每个同步槽必须独占一条 64B cacheline。如果两个信号变量挤在同一条 cacheline，对端的并发写会互相"冲掉"（伪共享 + 写合并），出现信号丢失——源码注释里专门给了这个反例。SHMEM 的 sync_pool 按 ACLSHMEM_SYNCBIT_SIZE=64B 切槽保证这一点。

7.2 集合 barrier：从"点名"到"散播"

SHMEM 的 device 侧 barrier 是两级结构：先 sync_core（本 NPU 内多核对齐，优先硬件 SyncAll，退化为软件对数散播），再 sync_npu（跨 NPU，四代算法按 team 大小自动选择）：

算法思路信号量适用
v1 散播经典 dissemination：每轮向"距离 ×2"的邻居发信号并等"距离 ÷2"的邻居N·log₂N通用基线
v2 分组散播k 元散播，一轮联系 k−1 个邻居N·log_k N大 team 降轮数
v3 集中拉取各 PE 写自己槽，前 k 个 AIV 轮询拉取所有远端槽，再放行N 次读team ≤ 32 或 AIV 数充足
v4 k 元推送AIV0 推送"代次计数"，其余核相位轮询本地 GM（避免远端轮询）~N大 team 主力（radix 32→320 / 16→2816 / 8→更大）
🎮 图 7-1 · Barrier 算法动画模拟器（选算法和 PE 数，点播放，观察轮数与信号量）
选择算法后点"播放"。
v1 的精髓：步长每轮翻倍（1→2→4…），log₂N 轮后所有人都"知道"了所有人；每个 rank 每轮恰好收发 1 个信号，负载完全均匀。v3 则把"N 个写"换成"root 的 N 个读"。
src/device/gm2gm/shmemi_device_cc.h · v1 散播核心（节选）
for (shift = 1; shift < size; shift <<= 1) {              // 步长翻倍：1,2,4,…
    partner_dst = (my_pe + shift) % size;                 // 向"下游"发信号
    partner_src = (my_pe + size - shift) % size;          // 等"上游"的信号
    // 信号 = 代次计数（generation counter），天然免疫上一轮残留
    aclshmemi_signal_set(&sync_pool[team][partner_dst][slot], pe_map, counter);
    aclshmemi_wait_until_eq_for_barrier(&sync_pool[team][my_pe][slot], counter);
}
🔑
为什么信号是"计数"而不是"布尔"？每个 team 的同步槽会被反复使用。若用 bool 置位，上一轮残留的 true 会让下一轮"秒过"（假同步）。用每轮 +1 的 generation counter，等待条件是"值 ≥ 本轮代次"，历史值天然失效。这正是 SYNC_ARRAY_SIZE 里给每 team 预留多槽 + 计数的原因。
🔬 深入：v3/v4 的调度细节与 A2/A3 的 FFTS
  • 调度：aclshmemi_sync 里 team_size≤32 或 AIV 数 ≥ team_size 时选 v3，否则 v4；v4 的 k 按容量公式选（32/16/8），slot 容量由 SYNC_ARRAY_SIZE / SYNCBIT_SIZE 决定。
  • vec 变体：aclshmemx_barrier_vec（ACLSHMEM_GLOBAL_VECTOR，core_ratio 0:1 纯矢量核）只同步矢量核；普通 barrier 同步全部核。
  • FFTS：A2/A3 上 barrier kernel 入口先 SetSyncBaseAddr(util_get_ffts_config()) 启用芯片级快速同步单元做核内对齐；950 不用 FFTS，改为 team 同步池方案。
  • 语义差别：sync 只保证本地 store 可见；barrier 额外保证此前远程操作完成（实现上 barrier=sync<false>，quiet 语义并入）。

12术语速查（可搜索）

输入关键词过滤；覆盖文档与接口中出现的主要缩写。

术语展开含义
PEProcessing ElementSHMEM 通信参与者编号（一个进程/rank/设备方）
PGASPartitioned Global Address Space分区全局地址空间编程模型（对称内存的学术名）
Team—通信域：一组 PE 的子集，限定同步/集合操作范围；WORLD=0 默认全域
对称堆Symmetric Heap各 PE 各持一块等长堆；同序同大小 malloc 得到相同偏移
RMARemote Memory Access单边远程内存访问（put/get）
AMOAtomic Memory Operation原子内存操作（add/swap/cas…）
SOSignal Operation信号操作：put-with-signal、signal_wait_until 等
MOMemory Ordering内存保序：quiet/fence 保证完成与顺序
NBINon-Blocking Immediate*_nbi 后缀：立即返回，需配 quiet/fence
quiet / fence—等待本 PE 先前操作完成；fence 当前实现等价 quiet
MTEMemory Transfer EngineAICore 侧搬运引擎（MTE2: GM→UB / MTE3: UB→GM 流水级）
UBUnified BufferAICore 私有高速暂存（也是 MTE 流水的 staging）
GMGlobal Memory全局内存（HBM），对称堆所在
SDMASystem DMA系统级 DMA（STARS 引擎，SQE 队列化，仅 910A3）
RDMA / RoCERemote DMA over Converged Ethernet跨节点直接内存访问；verbs 风格 WQE/SQ/CQ
UDMAUnified DMA950 统一 DMA，走 UB 灵衢总线（EID/jetty/token）
UB 总线（灵衢）Unified Bus华为新一代统一互联协议；UBMEM 内存语义 / URMA 远程内存访问
HCCSHuawei Cache Coherent System910 服务器内 CPU/NPU 高速一致互联
SIOSerial I/O LinkA3 片内两个 Die 之间的互联通路
EIDExtended ID16 字节 UB 网络端点地址（subnet_prefix+interface_id）
jetty / token—UDMA 的服务入口（码头）与访问令牌；取代 rkey 时代的 MR 授权
MR / lkey / rkeyMemory RegionRDMA 注册内存域；lkey 本地访问键 / rkey 远程访问键
QP / WQE / CQEQueue Pair / Work/Completion QERDMA 队列对；工作队列元素（发件单）/ 完成队列元素（回执）
SQE / doorbellSubmission QESDMA/UDMA 提交队列元素；doorbell = 通知硬件取工单的"门铃"寄存器
HYBMHybrid Memory底层混合内存库：entity（内存域）/ slice（物理内存）/ GVA（预留虚址）
GVA / GVMGlobal Virtual Address/Memory全局虚拟地址（20T–24T 预留区），对称堆排布其中
device_state—Host 状态在 NPU 元数据区的镜像（固定 VA），算子里直接读
FFTS—910 代际芯片级快速同步单元（SetSyncBaseAddr 启用）
DCCI / DSBData Cache Clean & Invalidate缓存清理/失效指令：把标量 cache 刷回 GM，跨 PE 可见性的保障
dissemination—散播 barrier 算法：步长翻倍，log₂N 轮收敛
relay—UDMA 中继路径：借中继 PE 的端口 EID 转发到非直连对端
D2D/D2H/H2D/D2rH/rH2DDevice/Host × 本/远通路记法：设备到设备 / 设备到主机 / 到远端主机…
CMOCache Maintenance Op缓存维护操作（如 L2 prefetch，sdma cmo_nbi）
aclgraph—昇腾整图捕获执行；SHMEM RDMA 支持在图中调用（rdma_aclgraph_demo）
高阶/低阶接口high-level / low-level屏蔽引擎的封装接口 vs 直接暴露引擎语义的接口（engine/ 目录）
